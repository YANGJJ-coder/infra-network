# BandwagonHost Phase 1.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不安装任何代理、面板、Web 服务或监控栈的前提下，为 `80.251.216.245` 建立可审计、可恢复、可重复执行的长期运维基线。

**Architecture:** 本地维护一个幂等 Bash 脚本并安装到 `/usr/local/sbin/bwg-phase1.5-init.sh`。脚本在修改 SSH 与 Docker 配置前复制原文件至 `/var/backups/bwg-phase1.5/<UTC timestamp>/`，将所有 stdout/stderr 追加到 `/var/log/bwg-phase1.5.log`，并生成同目录恢复脚本。配置采用 drop-in：`/etc/ssh/sshd_config.d/99-bwg-phase1.5.conf` 与 Docker JSON 深度合并，避免覆盖既有配置。

**Tech Stack:** Ubuntu 24.04、OpenSSH、Docker CE、Python 3 标准库 JSON、apt、systemd。

## Global Constraints

- 不安装 WireGuard、sing-box、Xray、Hysteria2、Reality、x-ui、3x-ui、nginx、Caddy、Traefik、Prometheus 或 Grafana。
- 所有目录和配置写入前检查状态；重复运行返回 0，且不重复添加 UFW、用户组、SSH Key 或目录。
- 保留 Root，但最终 SSH 状态必须为 `PermitRootLogin prohibit-password`、`PasswordAuthentication no`、`PubkeyAuthentication yes`、`KbdInteractiveAuthentication no`、`ChallengeResponseAuthentication no`、`UsePAM yes`。
- 只有本机 `~/.ssh/id_ed25519.pub` 已导入 Root 与 `yjj` 且以 key-only SSH 成功验证后，才写入 SSH 加固配置并 reload sshd。
- 保持 Phase 1 的 journald 限制不变。

### Task 1: SSH 安全、备份和恢复

**Files:**
- Create: `/Users/yjj/Documents/BandwagonHost/bwg-phase1.5-init.sh`
- Create on server: `/usr/local/sbin/bwg-phase1.5-init.sh`
- Create on server: `/var/backups/bwg-phase1.5/<timestamp>/restore.sh`
- Create on server: `/etc/ssh/sshd_config.d/99-bwg-phase1.5.conf`

**Interfaces:**
- Consumes: `/Users/yjj/.ssh/id_ed25519.pub`
- Produces: `yjj` 用户、两份 `authorized_keys`、SSH drop-in、可执行恢复脚本。

- [ ] **Step 1: 记录失败前置状态**

Run: `sshd -T | grep -E 'permitrootlogin|passwordauthentication|pubkeyauthentication'`

Expected: 当前 `permitrootlogin yes` 与 `passwordauthentication yes`，证明加固前测试会失败。

- [ ] **Step 2: 创建并验证管理员访问**

Create `yjj` with `useradd -m -s /bin/bash -G sudo,docker,adm,systemd-journal yjj`; create `.ssh` directories with modes `0700`; append the public key only when absent; use `ssh -o BatchMode=yes -o PasswordAuthentication=no` to authenticate as both `root` and `yjj`.

- [ ] **Step 3: 写入最小 SSH drop-in 与恢复脚本**

Write exactly:

```text
PermitRootLogin prohibit-password
PasswordAuthentication no
PubkeyAuthentication yes
ClientAliveInterval 300
ClientAliveCountMax 3
KbdInteractiveAuthentication no
ChallengeResponseAuthentication no
UsePAM yes
```

Run `sshd -t` before `systemctl reload ssh`; make `restore.sh` restore backed-up paths and reload only after a successful `sshd -t`.

- [ ] **Step 4: 验证 SSH 加固**

Run `sshd -T` plus key-only SSH as both users. Expected values: `prohibit-password`, `no`, `yes`, `300`, `3`.
